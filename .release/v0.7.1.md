# v0.7.1 — 拖拽宽度不再卡顿，外加 0.7.0 的全部修正

这一版是 0.7.0 的返工版。0.7.0 曾短暂发布到 GitHub 并被撤回（npm 未发布），原因是它在拖拽宽度时
明显变卡。0.7.1 保留 0.7.0 所有正确的修正，把错误的那一条换成正确做法。

## 撤回的那一条：宽度变化

0.7.0 为了「宽度变了行高就错了」，监听了 window.resize：防抖 200ms，清空全部行高与块高缓存，
摘掉所有标记，再重扫整页。思路对，做法错——它把一个只影响少数行的变化变成全量重建，而且正好
发生在用户拖拽过程中。

真正的问题在更早的地方，0.6.0 就有。拖拽时被 ResizeObserver 观察的行（最多 200 行）在同一帧
全部改变宽度，回调随即收到 200 个条目，而回调对每个条目都做「读 getBoundingClientRect →
读 getComputedStyle → 写样式」。读写交替，每次读都强制重新布局一遍。

修法：回调里什么也不测。ResizeObserverEntry.contentRect 本身就是内容盒，正好是
contain-intrinsic-size 描述的那个盒子。再加一条「与当前值相差不到 0.5px 就不写」。
**窗口级 resize 监听整个不需要**：宽度变了的行本来就会各自报一次。

| 600 行 / 观察 200 行 / 拖拽 120 帧 | 0.6.0 与 0.7.0 | 0.7.1 |
| --- | --- | --- |
| 每帧 getBoundingClientRect 次数 | **390** | **0** |
| 拖拽期间总 rect 读 | **46800** | **0** |
| 长帧（>25ms） | 0 | 0 |

长帧数看不出差别——帧间隔被 vsync 钉在 16.7ms，工作量再大，只要还在预算内就只是「刚好赶上」。
所以判据是 rect 读次数，不是帧时间。

## 保留的 0.7.0 修正

**行高改用字面量。** contain-intrinsic-size: auto var(--sb-h) 比 auto <N>px 慢约 6 倍
（18.1ms vs 2.8ms，块级早已验过），因为每个被跳过的盒子每次样式重算都要解析一次自定义属性。
行数比块数还多一个量级。现在直接写 auto <N>px；--sb-h 保留，只作 report() 与人工排查的读数。

**表面表会自己收敛。** discoverSurfaces() 原来只往里加，切会话、开关轨迹面板之后旧元素永远留着，
连同 rows 集合一起钉住一棵已经脱离文档的子树。现在每次发现都跑 pruneSurfaces()，
MutationObserver 也看 removedNodes。

**bfcache 回退不再永久失效。** 原来 pagehide 注册的是 destroy 加 { once: true }，从浏览历史后退
回来时插件已被拆干净。现在 pagehide 只在 event.persisted 时走 pause()，pageshow 再 resume()。

**will-change 可以关。** window.__scrollBoost.setPixelSafe(true) 停用 B 层，A/F/G 照常。
这是唯一会改像素的一层（LCD 子像素 → 灰度抗锯齿）。

**三个新 hint 表面**：[data-input-scroll]、[data-approval-scroll]、[data-question-scroll]。
都是面板内有 max-height 的滚动口，没有行可跳，加进来是为了让空闲扫描在用户滚动它们时暂停。
文档缩放视口 [data-document-zoom-scrollport] 有意不加。

**块高进 localStorage**：键是「最近的稳定祖先 key + 子节点索引路径」，没有稳定 key 的正文不缓存。

## 清理

- markRow()：applyBatch() 之后没有任何调用方；
- rowsThisSlice 累加器；
- 永不触发的 measure: false 分支；
- data-scrollboost-scrolling 属性及其每容器清理定时器（没有任何 CSS 或代码读它）；
- 四个只写不读的 state 字段（guardedRows、fastBudgetUntil、overflowDone、overflowHandle）；
- 两处不一致的滚动阈值：溢出扫描曾用 +80，其余用 +4，现在统一为 SCROLL_OVERFLOW_SLACK；
- report().marked 改为与 rows 同口径的实时计数（原来跨扫描累加，多扫几轮就会大于 rows）。

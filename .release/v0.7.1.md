# v0.7.1

三个改进：拖拽宽度不再卡顿、离屏行跳过更快、长时间使用不再泄漏。全部不改变画面。

## 一、拖拽宽度不再卡顿（最重要）

拖动会话的宽度手柄时会卡。原因在插件的行 `ResizeObserver` 回调里：对每个条目都做
「读 `getBoundingClientRect` → 读 `getComputedStyle` → 写样式」，读写交替，每次读都把刚标脏的
样式重新布局一遍。

拖拽时被观察的行（最多 200 行）**在同一帧全部改变宽度**，回调随即收到 200 个条目——于是这就是
200 次强制同步布局，而且正好发生在你拖动的过程中。

修法是回调里什么也不测：`ResizeObserverEntry.contentRect` 本身就是内容盒，正好是
`contain-intrinsic-size` 描述的那个盒子。再加一条「与当前值相差不到 0.5px 就不写」，纯宽度变化
就不必把每行样式都标脏一次。

| 600 行 / 观察 200 行 / 拖拽 120 帧 | 0.6.0 | 0.7.1 |
| --- | --- | --- |
| 每帧 `getBoundingClientRect` 次数 | **390** | **0** |
| 拖拽期间总 rect 读 | **46800** | **0** |
| 长帧（>25ms） | 0 | 0 |

长帧数看不出差别——帧间隔被 vsync 钉在 16.7ms，工作量再大，只要还在预算内就只是「刚好赶上」。
所以判据是 rect 读次数，不是帧时间。

## 二、行高改用字面量

`contain-intrinsic-size: auto var(--sb-h)` 改成直接写 `auto <N>px`。每个被跳过的盒子在每次样式
重算时都要解析一次自定义属性，实测比字面量慢约 **6 倍**（18.1ms vs 2.8ms）——块级早就验过，
行级现在跟上。行数比块数还多一个量级。

`--sb-h` 仍然写，只作为 `report()` 和人工排查的读数。

## 三、长时间使用不再泄漏

**表面表会自己收敛。** 切会话、开关轨迹面板之后，旧元素原本永远留在内部表里，连同它的行集合
一起钉住一棵已经脱离文档的子树。现在每次发现都做一次剪枝，`MutationObserver` 也看 `removedNodes`。

**bfcache 回退不再永久失效。** 从浏览历史后退回来时，插件原本已经被拆干净、`window.__scrollBoost`
也没了。现在 `pagehide` 只在真正进 bfcache 时暂停调度（保留标记与缓存），`pageshow` 再恢复。

**块高进 localStorage。** 键是「最近的稳定祖先 key + 子节点索引路径」，没有稳定 key 的正文不缓存
（纯索引会跨正文撞车）。长会话重开后，展开过的思考正文不必重新测量每个块。

## 四、新增

**`setPixelSafe(true)`。** `will-change: scroll-position` 会把滚动口提成独立合成层，文字从 LCD
子像素抗锯齿变成灰度——几何和 `scrollHeight` 都不变，但同位置截图会差几万个像素。这层收益真实
存在，但不是人人都想要，所以做成运行时开关。关掉后 A/F/G 三层照常工作。

```js
window.__scrollBoost.setPixelSafe(true);   // 只要逐像素一致
window.__scrollBoost.setPixelSafe(false);  // 恢复默认
```

**三个新的滚动口识别。**「输入框」「审批面板」「提问面板」这三个内部滚动容器现在也被认出来。
它们没有行可跳，加进来是为了让空闲扫描在用户滚动它们时暂停。文档缩放视口有意不加——它是缩放
变换的目标，加合成提示会改变文档的栅格化方式。

## 五、清理

- 删掉一个没人调用的打标记函数、一个算出来就没人读的累加器、一段永不触发的分支；
- 删掉一个没有任何 CSS 或代码读取的属性及其每容器清理定时器；
- 四个只写不读的内部状态字段；
- 两处不一致的滚动阈值：原来溢出扫描用 `+80`、其余用 `+4`，差 5–80px 的容器会被一条路径收下、
  被另一条漏掉。现在统一为一个常量；
- `report().marked` 改为与 `rows` 同口径的实时计数（原来跨扫描累加，多扫几轮就会大于 `rows`）。

## 测试

新增 `test/probe-resize-plugin.html`：按帧模拟拖拽，统计被标记行上的 rect 读次数——这是拖拽是否
卡顿的直接判据，已接进 `npm run test:browser`。

回归测试新增一条硬断言：jsdom 没有 `ResizeObserver`，测试自带可控替身，投递条目时若发生任何
rect 读即失败。对旧实现运行会得到 `actual: 2, expected: 0`，所以这个 bug 不会悄悄回来。

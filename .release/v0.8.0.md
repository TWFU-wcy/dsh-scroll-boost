# v0.8.0

**新增一个设置页**：告诉你插件能优化哪些界面，并让你按界面类型或按具体容器关掉任意一处。
没有删掉任何已有优化。

## 一、设置 → Scroll Boost

侧栏进入 **设置**，列表里有一条 **Scroll Boost**。页面分上下两段。

### 上半段：能力清单（常驻）

7 项界面，**不需要真的打开那些页面**：

| 界面 | 插件在这里做什么 |
| --- | --- |
| 聊天记录 | 让屏幕外的消息不参与布局和绘制 |
| 会话滚动区 | 提示浏览器把滚动容器单独提升一层 |
| 轨迹面板 | 跳过屏幕外的内容单元格 |
| 摘要预览 | 不做跳过，只用于滚动时暂停后台扫描 |
| 输入框 | 同上 |
| 审批面板 | 同上 |
| 提问面板 | 同上 |

每项标注「本页 / 不在此页」，**右侧带开关**——即使那一页当前没打开也能关掉。

### 下半段：当前页检测结果

点 **重新检测** 扫一遍文档，列出当前页面所有可加速项，**已开启的置顶**。关掉的沉到下面但不会消失。

这一层是快照，不会自己跳动。

### 可读性

默认视图里没有 CSS 选择器、没有属性名、没有长 key：

- 名称是「聊天记录」「输入框」这类人话，按形状收进来的第三方页面显示为「其他插件的面板」；
- key 收进 **技术信息 ▸**，默认不显示；
- 字号 15/13/12/11px 分级，全部继承主题字体，只用 `--dsw-alias-*` 变量，无写死颜色。

界面语言在页面内切换：**中文 / English**，**默认中文**，选过会记住，未选过时跟随 DSH。
设置列表里的条目名固定为 **Scroll Boost**，不随页面语言变化。

## 二、两种开关

| 层级 | 作用范围 | API | 存储键 |
| --- | --- | --- | --- |
| 按界面类型 | 这一类界面，**对没打开的页面也有效** | `excludeKind(id)` | `excludedKinds.v1` |
| 按具体容器 | 这一个滚动容器 | `exclude(key)` | `excluded.v1` |

类型开关记的是 `trajectory`、`chat-flow` 这样的表面 id，与页面层级无关，所以 DSH 改版后也不会
失效——这是它比容器开关更耐用的原因。

关掉后该范围内行标记、钉死高度、`--sb-h`、合成提示、分块标记全部移除，**和没装插件一样**，
其它界面照常优化。重启仍然有效。

## 三、修掉的一个真 bug

做类型开关时发现：关掉「聊天记录」后标记**清了又回来**。

原因是类型排除只拦住了 `SURFACE_DEFS` 那条路，通用行列表通路不查它，下一次扫描又把行标回去。
已在 `guardReason()` 和分块通路补上检查，现在关掉后重扫仍是 0 标记。

## 四、检测开销，实测

| 操作 | 布局读取次数 |
| --- | --- |
| 能力清单 `catalog()` | **0 次**（7 次 `querySelector`） |
| 全文档扫描 `discoverAll()` | **1650 次** |

在 2854 节点的文档上测的。所以清单可以随每次打开设置页刷新，全文档扫描只在你点「重新检测」时跑。

**没有做「遍历 DSH 所有页面」**：没打开的页面不在 DOM 里，要检测就得先挂载它——那是真的渲染，
画面会闪，还可能触发副作用。而它们对应的正是清单里那 7 项，清单已经给出了同样的信息。

## 五、这一版没有删掉什么

开发过程中我一度删掉过两样东西（轨迹表静态规则、按形状找列表的通路），理由是怀疑它们造成了另一个
插件的页面卡顿。后来用 0.7.2 与 0.8.0 跑同结构对照，结果：

- 轨迹表：0.7.2 会给滚动口加合成提示、并由静态规则跳过内容单元格；删掉后收益一并消失；
- 市场类卡片页：0.7.2 会跳过屏幕外卡片；删掉后卡片全部重新参与渲染。

而那个「卡顿归因」从未被证实。用未证实的假设换掉真实收益不划算，所以两者都恢复了。0.8.0 相对
0.7.2 是**纯增量**。

从「猜列表」到「认表面」：聊天页第一次真正被优化，行高改成真值，护栏补齐。

## 为什么要改
0.2.x 的做法是「在页面里找一个看起来可滚动的容器，再把它的直接子节点当成行」。
但 DSH 把聊天记录渲染进一个 `display: contents` 的槽位——槽位自己没有盒子，
那套「向下走直到找到行列表」的搜索永远看不到它，**长会话聊天页基本没被优化过**。

## 变更
- **认表面**：直接认 DSH 自己的稳定 `data-*` 属性，按表面类型决定策略。
  - `chat-flow`（`[data-slot="conversation.chat.flow"]`）→ 标记其直接子行
  - `conversation-scroll`（`[data-conversation-scroll]`）→ 只加 `will-change` 提示
  - `summary-region`（`[data-summary-scroll-region]`）→ 只加提示
  - 认不出来的界面仍走 0.2.x 的通用回退路径
- **行高真值**：DSH 自己的「当前读到第几行」是拿 `getBoundingClientRect()` 做二分的。
  占位高度和真实高度对不上，跳转与跟随尾巴就会落到错误的行。
  - 离屏行不读布局，直接用按 `data-chat-flow-key` 记住的历史高度（WeakMap + localStorage）
  - 可见带才实测一次，且减去 padding / border（`contain-intrinsic-size` 描述的是内容盒）
  - 一个分片里的行先全部读完、再全部写入，把每行一次布局重算压成每批一次
- **护栏**：sticky/fixed 行、`display: table-*`、`contenteditable`、`aria-live`、
  折叠/展开动效中的行、以及任何带粘性后代的容器，一律跳过；`report().skipReasons` 能看到原因。
- **变更去抖** 300ms → 50ms，切到轨迹/会话视图后更快跟上。
- `report()` 新增 `surfaces`（认出了哪些界面、各标了多少行）与 `skipReasons`。

## 实测
- 聊天页夹具（600 行，含粘性横幅）：rows 599 / marked 599，粘性行正确跳过。
- 漂移探针：600/600 标记，`scrollHeight` 28426 前后一致，`maxHeightDrift` 0。

## 安装
```powershell
dsh plugin --profile desktop add "github:TWFU-wcy/dsh-scroll-boost"
```
安装后完全重启 DSH。

这一版**轨迹页没有优化**，见 0.4.0。

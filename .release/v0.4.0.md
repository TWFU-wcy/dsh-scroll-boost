轨迹页修复：0.3.0 把轨迹页整面跳过了，这一版用一条静态 CSS 规则补回来，画面零变化。

## 问题
0.3.0 把轨迹页标成 `skip`，理由是「DSH 自己做虚拟化」。这个判断只对了一半：
虚拟化确实在，但它在**滚动时每帧重建 `<tr>`**（`tbody.replaceChildren`）。
插件原本的打标记方式是「读一次高度 → 写一个 `data-*` 属性」，属性写上去的下一帧就被新节点换掉了，
等于什么都没做——所以 0.3.0 之后轨迹页的手感反而回到没装插件时。
（0.2.1 反而会走通用路径去标记，这才是「0.3.0 比之前更卡」的真实来源。）

## 变更
轨迹页改用一条**静态 CSS 规则**：规则随样式表一次性生效，浏览器在它自己的样式计算里应用，
不需要主线程逐行写 DOM，也就不会被重建冲掉。

```css
[data-trajectory-scroll] tbody tr[data-record-index]:not([data-turn-start]):not([data-terminal-request-boundary]):not([data-request-only]):not([data-collapsed-summary]) > td:last-child {
  content-visibility: auto;
  contain-intrinsic-size: auto 30px;
}
```

三个约束来自对真实轨迹表的像素级验证：

- **只标内容单元格**（`td:last-child`）。事件列里有绝对定位、故意越界的 `turnRail` 与
  `requestBoundaryControl`，`content-visibility` 的 paint containment 会把它们裁掉。
- **排除 `data-turn-start` 行**。这类行用 `td:before` 在自己上边缘画 1px 分隔线，同样会被裁。
- **排除非标准高度行**（9px 边界行、0px 请求行、24px 折叠摘要行）。它们的占位高度和真实高度
  不一致，会让滚动条漂移。

另外：`content-visibility` 在 Chromium 上对 `tr` / `td` 本身不生效，标 `td` 时真正被跳过的是
**td 的直接子元素**——这一点用 `checkVisibility({contentVisibilityAuto:true})` 验证过，
只看 `getComputedStyle` 会被误导。

## 实测（2000 行虚拟化轨迹表，每帧重建 46 行，富文本内容）
| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 每帧脚本 + 布局 median | 6.3 ms | **5.0 ms**（−21%） |
| 每帧脚本 + 布局 p95 | 11.6 ms | **8.3 ms**（−28%） |
| `scrollHeight` | 59917 | 59917（0 漂移） |
| 行高集合（普通/请求/折叠/边界） | 30 / 19 / 24 / 20 | 完全一致 |
| 同位置截图像素 diff | — | **0** |

## 安装
```powershell
dsh plugin --profile desktop add "github:TWFU-wcy/dsh-scroll-boost"
```
安装后完全重启 DSH（不是刷新页面）。

验证：

```js
window.__scrollBoost.report().version   // "0.4.0"
window.__scrollBoost.report().surfaces  // trajectory 的 kind 应为 "static"
```

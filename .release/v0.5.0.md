# v0.5.0 — 长思考正文按块跳过

展开一条很长的思考过程（尤其是 PTC 模式下多轮 reasoning 叠加）后滚动依然会卡。这一版处理的就是它。

## 问题在哪

整段思考正文是**一个** Markdown 子树，高度远超视口。之前的「按行跳过」对它完全无效：
它在视口里，`content-visibility` 就不生效，每帧都要对整棵子树重做一次 style + layout。

## 怎么解决

把跳过粒度从「行」下沉到「块」：只在思考正文的根上工作，给它高度超过 1.5 屏的直接块子元素
（段落、代码块、列表、宽表）逐个打标记。

```css
[data-scrollboost-chunk] {
  content-visibility: auto;
  contain-intrinsic-size: auto 120px;
  contain-intrinsic-size: auto var(--sb-chunk-h, 120px);
}
```

命中根用 `[data-markdown-variant="compact"]`——DSH 只在思考正文上输出这个属性，普通回答的
Markdown 没有，所以不依赖任何哈希类名。

### 必须先钉真实高度

块在离屏时读不到布局，`contain-intrinsic-size` 若给估算值，整段正文的 `scrollHeight` 会塌掉
（实测 480 块时漂移 −23444px），页面顶部 sticky 的思考头也会被顶出屏幕。所以每个块都是
「先量 → 再钉 → 后打标」，并且：

- 流式输出中的正文一律不动，它的文字每个 token 都在变，钉住的高度立刻过期；
- 流结束时 `data-state` 翻转、但没有任何节点新增，这条属性变化本身会触发一次分块；
- 块数量变化时（React 重建了正文）整组解钉重来，不留过期占位；
- `disable()` 把所有 `--sb-chunk-h` 与标记清干净，`scrollHeight` 完全还原。

## 实测

12 个思考块组 × 42 块、真实类名、headless Edge：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 每帧脚本+布局中位数 | 3.3 ms | **0.2 ms** |
| 每帧脚本+布局 p95 | 6.3 ms | **0.3 ms** |
| `scrollHeight` | 48512 | 48512（不变） |
| 正文根高度 | 4016 | 4016（不变） |
| sticky 思考头位置 | 41 | 41（不变） |

离屏块 `checkVisibility` 确认被跳过；`disable()` 后块标记清零、`scrollHeight` 还原。

## 安装

```powershell
dsh plugin --profile desktop add "github:TWFU-wcy/dsh-scroll-boost"
```

装完必须**完全退出并重启 DSH**（不是刷新页面）。之后在 Console 执行：

```js
window.__scrollBoost.report()
```

`version` 应为 `0.5.0`，展开长思考后 `chunks` / `chunkRoots` 应大于 0。

## 回滚

```js
window.__scrollBoost.disable()   // 立即还原 DOM
```

或装回 `v0.4.1`。
